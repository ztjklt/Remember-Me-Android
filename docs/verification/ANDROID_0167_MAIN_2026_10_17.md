## Contract 与数据库

引入来源已经批准的独立 `contact-entrustment-v1` schema，及 `twin-recall-v1` 的可选信件关联；冻结的旧 schemas 保持。授权与配置说明见 [联系方式托付提案](../architecture/contact-entrustment-20261017.md) 和 [亲友托付交接](../team/CONTACT_ENTRUSTMENT_HANDOFF_20261017.md)。

```bash
cd services/backend
uv sync --locked
uv run --locked alembic upgrade head
```

新增 `cryptography>=46,<51` 已进入锁文件。首次部署/升级必须使用此版本的后端和 AI Core；只替换 APK 不会更新服务端行为。既有服务启动、ASR、DeepSeek 与小米 TTS 配置继续沿用相应环境，不能以 iOS CloudBase 配置替换。

托付渠道配置模板：`services/backend/.env.contact.example`。需要稳定保存 `REMEMBER_CONTACT_ENTRUSTMENT_KEY`、正确的 HTTPS 根地址和至少一种真实发送渠道；反向代理需放行 `/receive/` 与 `/api/v1/entrustment-receipts/`。未配置时按实现关闭对应能力，不伪称已经送达。本轮未创建密钥、开通短信服务或发送真实邮件/短信。

`internal` 构建设置 `DEMO_ACCOUNTS=true`，沿用源码的虚构陈守义账号迁移/切换；普通 `debug` / `release` 默认为 false。部署到实际账号环境前需确认使用的构建类型和演示账号功能配置。新库不会通过本次合入执行旧测试账号清理；历史验证文档中的服务器清理是当时另一次操作的记录。

## Android 构建

JDK 17、Android SDK 35，普通模拟器包：

```bash
cd apps/android
./gradlew --no-daemon testDebugUnitTest assembleDebug -PrememberServiceUrl=http://10.0.2.2:8891
```

录音豆版本仍需私下提供厂商 AAR，并补充 `-PrememberSoundcoreSdk=<本机绝对路径> -PrememberRequireHardwareSdk=true`；云端 internal 包按已有签名配置构建。默认 debug 包连接模拟器宿主机，不是已签名云端安装包。版本后缀沿用现有构建逻辑。
